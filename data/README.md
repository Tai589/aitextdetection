# 数据说明

此目录保存本项目实际运行需要的冻结数据。五个 CSV 与其来源实验中的对应文件逐字节一致，没有因整理目录重新抽样、重新划分或修改正文。

## 来源和使用范围

- 数据集：`liamdugan/raid`。
- 上游分区：公开 `train`。
- 领域：`news`、`reviews`、`wiki`。
- 生成器标签：`chatgpt`、`gpt4`、`mistral`，以及人类文本 `human`。
- 保留条件：无攻击文本，固定既有 decoding 和 repetition penalty 条件，具体记录见 `dataset_config.json`。

本项目在 RAID 公开训练分区内部形成自己的来源分组划分。这里的测试文件不是 RAID 官方测试分区，成绩不能当作官方榜单成绩。

数据来自 [RAID 数据卡](https://huggingface.co/datasets/liamdugan/raid) 所列的公开材料，上游标注为 MIT 许可。数据正文和元数据不属于本项目原创；随包保留的上游版权与许可全文见 [RAID-MIT.txt](../LICENSES/RAID-MIT.txt)，引用及许可范围见 [第三方说明](../THIRD_PARTY_NOTICES.md)。

数据准备阶段曾形成 10,000 条、2,500 个来源的样本。当前目录只保留实验实际需要的五份划分，不包括原始大文件、完整样本副本或明确排除的记录。本项目从这些冻结输入开始，未提供从上游原始数据重新取样的入口。

## 五份划分

| 文件 | 文本数 | 人类 | AI | 用途 |
|---|---:|---:|---:|---|
| `train.csv` | 2,634 | 878 | 1,756 | 拟合特征与分类器；来源准入只改变此分区。 |
| `validation.csv` | 1,572 | 524 | 1,048 | 所有训练方案共用；选择 `C` 和阈值。 |
| `test_id.csv` | 1,044 | 348 | 696 | 熟悉的领域和生成器，来源未用于开发。 |
| `test_domain.csv` | 2,250 | 750 | 1,500 | 留出的 `wiki` 领域。 |
| `test_generator.csv` | 696 | 348 | 348 | 留出的 `mistral` 生成器，及人类对照。 |

开发数据只使用 news/reviews 和 human/chatgpt/gpt4。训练与验证来源中对应的 Mistral 输出被排除，不用于训练、选参或阈值校准。

`test_id.csv` 与 `test_generator.csv` 共享 348 条人类对照，这是固定设计的一部分。五份文件的行数相加不等于独立文本数。两个测试场景间的共享对照不属于训练泄漏，但意味着两份成绩不能视为完全独立证据。

## 主要字段

| 字段 | 含义 |
|---|---|
| `id` | 当前文本记录的编号。 |
| `source_id` | 与这条记录关联的共同来源编号。 |
| `label` | 人类为 `0`，AI 为 `1`。 |
| `model` | human、chatgpt、gpt4 或 mistral。 |
| `domain` | news、reviews 或 wiki。 |
| `text` | 原始正文；文本检测器使用的输入。 |
| `text_sha256` | 正文摘要，用于完整性和重复检查。 |
| `word_count` | 正文按空白分隔得到的词数，不是 tokenizer 的 token 数。 |
| `adv_source_id` | 上游来源关系字段，保留以便校验。 |
| `decoding` | 上游生成时的解码条件。 |
| `repetition_penalty` | 上游生成时的重复惩罚条件。 |
| `attack` | 上游攻击条件。 |
| `title`、`prompt` | 上游元数据，不作为文本检测器的特征输入。 |

生成器、领域、来源编号、标题和提示词可用于审计与解释，不能作为正文分类器的输入特征。长度模型是单独的诊断对照：从正文重新统计词数，再使用其对数变换；缓存的 `word_count` 也会核对。

## 来源与近重复组件

同一来源的文本可能共享主题或内容。直接把这些行随机分给训练和测试，会使评价偏乐观。因此，既有划分按来源及已检查到的近重复关系分组。

`split_manifest.json` 的 `source_assignments` 为来源记录组件、分区和领域。组件由来源关系及词语近重复检查形成。检查覆盖已定义规则，不保证发现所有语义近重复。

新实验在冻结前只核对训练、验证及必要元数据，训练后保存冻结清单，再校验和读取测试文件。已完成运行的事后核验会检查全部登记文件。

## 清单和派生关系

| 文件 | 作用 |
|---|---|
| `manifest.json` | 登记随包数据摘要、原始父清单摘要、保留文件的原路径及摘要。 |
| `dataset_config.json` | 逐字节保留的数据制备与模型配置。 |
| `split_manifest.json` | 明确声明为精简派生清单，保留当前读取、分组与核验需要的内容。 |

目录和清单整理不冒充原清单字节未变。`manifest.json` 同时记录父清单摘要与新文件摘要，使保留内容和派生操作可追踪。`dataset_config.json` 中的一些原制备路径指向当前未提供的历史文件；运行现有冻结实验不需要这些文件，也不会自动访问这些路径下载数据。

参考结果清单也绑定本包数据清单的摘要，防止只保留同一个来源名称、实际输入却已经不同。

不要直接改 CSV 后继续使用原清单。若需要形成新数据版本，应建立新的数据目录、清单、划分和实验记录，明确说明变化。

## 证据边界

这些测试数据在本研究之前已经观察过。当前分析属于既有测试上的探索，不能宣称是新数据上的独立确认。所有模型共用完整测试记录，不按测试长度筛选，也不根据测试成绩重新选择参数。

来源、领域和文本条件均有限，不能据此推断对所有语言、领域、生成器或真实使用环境都可靠。数据出处和字段记录应在后续报告中继续保留。
